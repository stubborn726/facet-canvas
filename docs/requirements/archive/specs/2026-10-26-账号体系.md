# 账号体系 Spec

> 归档样本：这是 0.2.0 已交付任务的回填文档，用来给 `docs/README.md` 的模板提供**真实样例**。
> 交付日期 2026-10-26｜对应 CHANGELOG `[0.2.0]`

## 目标 / 背景

原来只有两个**全局共享口令**（一个编辑、一个只读），由此产生四个问题：

1. 无法单独收回某个人的权限（想让他只读，只能换掉所有人的口令）
2. 角色写死在令牌里（有效期 365 天）——降权/删人**不生效**
3. 登录时填的"姓名"是自由文本，版本历史里的"谁改的"不可信
4. 改口令必须动环境变量重启，普通人无法自助改密

目标：用账号体系替掉共享口令，做到"**降权 / 删人立即生效**"。

## 范围与不做（YAGNI）

- **做**：内置管理员、用户增删改、角色（admin/rw/ro）、自助改密、首次登录强制改密、忘记管理员口令的逃生通道
- **不做**：自助注册、邮件找回、密码强度策略、登录审计日志、用户组/项目级权限、多设备会话管理

## 输入与来源

- 现有鉴权代码：`server.js` 的口令常量、`issueToken` / `verifyToken`、`/api/login`、鉴权中间件
- 前端登录门：`public/app.js` 的 `doLogin` / `showGate`，`public/index.html` 的 `#gate`

## 口径与规则

| 主题 | 规则 |
|---|---|
| 存储 | `users(id, name UNIQUE, pass, role, must_change, created_at, updated_at)`；`pass` = `scrypt$N$r$p$salt$hash` |
| 角色 | `admin` 管用户 + 改画布；`rw` 改画布；`ro` 只看（服务端拦一切非 GET） |
| 令牌 | `{v:2, uid, exp}`，**不装角色**；每请求回库查 → 改角色/删用户立即生效；旧令牌一律失效 |
| 初始密码 | 管理员默认口令见 `docs/auth.md`（写在源码，公开仓库可见）；新用户/重置均为随机 26 位、只回显一次 |
| 强制改密 | `must_change=1` 时只放行 `/api/me`、`/api/me/password`，其余 403 |
| 口令优先级 | `ADMIN_PASSWORD` 环境变量 → 库 → 首次用默认值；环境变量是"忘记密码"的逃生通道 |
| 删除约束 | 不能删自己；不能删或降级**最后一个 admin** |
| 迁移 | `CREATE TABLE IF NOT EXISTS users` + 表空则建 admin；`meta.password/ro_password` 保留但不再读 |

## 产出

- `server.js`：users 表、scrypt 哈希、令牌 v2、鉴权中间件、6 个接口
- `public/{index.html,app.js,style.css}`：登录门改用户名+密码；账号菜单；用户管理弹窗；强制改密弹窗
- `test/smoke.js`：扩到 38 项（含权限与即时生效）
- `README.md` + `docs/auth.md`：文档同步

## 验收标准

- [x] 首次启动只能用 admin + 默认口令登录，进来被强制改密
- [x] admin 建 rw/ro 用户；ro 的任何写请求 403
- [x] admin 把某人改成 ro → 该用户下一次请求就被拦（不必重登）
- [x] admin 删除某人 → 该用户下一次请求 401
- [x] 普通用户不能调用 `/api/users*`，不能改别人密码
- [x] 用户改密后旧密码失效、新密码可登录
- [x] 不能删自己、不能删最后一个 admin
- [x] `ADMIN_PASSWORD=xxx` 能救回忘记的管理员口令
- [x] 令牌篡改 / 改 payload 用旧签名 → 401
- [x] 用户名注入（`<img onerror>`）在列表里被转义
- [x] 连续 8 次错误口令 → 429，锁定期内正确口令也 429
- [x] `npm test` 覆盖以上关键路径

## 开放问题（未在本版解决）

- 改密码**不踢掉其他设备**（令牌无版本号）→ 记入 README「已知限制」
- 密码策略只有 ≥6 位；限流按 IP（多 IP 可绕过）
- 默认管理员口令在源码里，靠 `must_change` 缓解；若删表重建会回到默认值
